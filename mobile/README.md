# mobile — Flutter applicant app (POC)

A Flutter applicant app that validates the **Flutter** mobile stack proposed in
the ITS RFP, running against this repo's existing CIB seven engine. It is
built and shipped exactly like the other components — **no local Flutter
install required** — and tested in a browser, including on a real phone.

## What it does (current step)

- **Sign in** with Keycloak (Authorization Code + PKCE) via the `cib7-mobile`
  public client.
- **My Applications** — lists the signed-in applicant's process instances
  (`GET /engine-rest/history/process-instance?startedBy=…`, bearer-authed),
  each with a coarse status (In progress / Approved / Closed). Mirrors the
  SPA's `MyProcessesPage`.
- **Application detail** — tap an application to see its documents
  (`GET /api/documents/{piId}`). When the case produced a
  `generated-certificate`, it shows as a wallet-style card: a verification QR
  (RFP FR 2.6), a **Download PDF** (presigned URL), and **Add to wallet**.
- **Wallet** tab — the certificates you saved, as scannable QR cards. Stored in
  `localStorage` namespaced per user, so a card renders offline; downloads
  still mint a fresh presigned URL. The card is shaped to map onto a real
  Apple/Google wallet pass later (the QR payload is the pass barcode).

Native iOS/Android builds (the `ios/`+`android/` targets exist in scaffolding)
land later; today only the `web` target is built.

## Why source-only (no committed `web/`, `android/`, `ios/`)

Only `lib/`, `pubspec.yaml`, and `analysis_options.yaml` are committed. The
platform scaffolding is regenerated by `flutter create` inside the Docker build
(`mobile/Dockerfile`), so the repo stays free of Flutter boilerplate. See
`.gitignore`.

## How it ships

`mobile/Dockerfile` builds the web app with the `cirruslabs/flutter` image
(Flutter runs inside Docker) and serves it from nginx — mirroring
`frontend/Dockerfile`. CI (`.github/workflows/docker-publish.yml`) publishes
`docker.io/krixerx/cib7-poc-mobile`. nginx serves the build physically under
`/mobile/` (`--base-href /mobile/`) and Traefik routes **`/mobile`** to it, so
on the server it lives at e.g. `https://companylab.ai/mobile` — open that on
your iPhone's Safari to test the Flutter stack on iOS hardware without an Xcode
build.

## Test locally with Docker (no Flutter install)

The engine must be up (the app calls `/engine-rest`). From the repo root:

```bash
docker compose up -d cib7 backend      # if not already running
docker compose up -d --build mobile
```

Then open **http://localhost:3001/mobile/**. You should see the **Services**
list loaded live from the engine. The mobile container's nginx proxies
`/engine-rest` to `cib7:8080`, so this works without Traefik.

> Heads-up: the first `--build` pulls the `cirruslabs/flutter` image (several
> GB) and downloads pub packages. On a tight C: drive this can be heavy — see
> the disk note in the repo's deployment docs.

## Local development (optional — needs Flutter installed)

The committed source is platform-agnostic. To run it locally:

```bash
cd mobile
flutter create --platforms web,android,ios --project-name cib7_applicant --org com.cib7 .
flutter pub get
flutter run -d chrome          # web
# Native iOS build requires macOS + Xcode (later step).
```

For a native build, point it at the public engine host:
`flutter run --dart-define=ENGINE_BASE=https://app.companylab.ai`.
