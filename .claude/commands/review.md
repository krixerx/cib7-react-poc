Review the staged changes against `backend-conventions`, `frontend-conventions` and `deployment-conventions`, and end with a verdict.

**Input**: Optionally a path or a commit range (e.g., `/review backend/`, `/review HEAD~3..HEAD`). If omitted, review the staged changes; if nothing is staged, review `git diff HEAD`.

**Steps**

1. **Collect the files**
   Run `git diff --staged --name-only` (or the range given) and group them:
   - **backend**: `cib7/**`, `backend/**` (`.java`, `application*.yaml`, `db/migration/**`)
   - **frontend**: `frontend/src/**`, `frontend/index.html`, `frontend/public/**`, `frontend/vite.config.ts`
   - **deployment**: `docker-compose*.yml`, `deploy/**`, `frontend/nginx.conf`, `frontend/docker/**`, `mobile/nginx.conf`, `esb/routes/**`, `keycloak/**`, `traefik/**`, `**/Dockerfile*`, `.github/workflows/**`
   Changes under `packs/test/` are generated by `/service-builder`; check only that the spec and generated files changed together.
   Report the list before going on.

2. **Load the rules**
   Read the SKILL.md of every group that has files. For each rule whose "Where" column points to `CLAUDE.md` or `docs/security.md`, read that section when the change could touch it.

3. **Read the changes**
   Read the diff, and the whole file where a rule needs context outside it: B3 and B7 (follow a controller into its service and the engine query), D1 and D3 (every `location` in the nginx file), D7 and D12 (every `ports:` item, not only the changed ones).

4. **Check each rule**
   For each violation record file, line, rule ID, severity and the exact fix. Cross-file checks to run every time:
   - **B10**: a changed `@Entity` with no new `backend/src/main/resources/db/migration/V*__*.sql`.
   - **B13**: a new endpoint with no test for a wrong role, another person's object and no token.
   - **D1**: any `proxy_pass http://` with a literal host.
   - **D10**: a change under `keycloak/` without the same change under `deploy/keycloak/`.

5. **Report**
   Group by file, most severe first (BLOCKER P1, P2, P3, WARNING, INFO):
   ```
   ## <file>
   BLOCKER P1  B3  L42  <snippet>
     Fix: <what to change>
   ```
   End with one verdict:
   - **BLOCKED**: any BLOCKER
   - **ALLOWED WITH WARNINGS**: only WARNING or INFO
   - **PASSED**: nothing found

**Guardrails**
- Do not run the test suites unless asked; `npm run typecheck` is fine as a cheap check.
- Fix only what the user asks you to fix. Ask before changing security, persistence or deployment code.
- Skip rules that do not fit the change; do not report "not applicable" lines.
